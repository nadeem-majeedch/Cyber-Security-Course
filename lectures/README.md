# Lectures (student-facing)

One directory per module; continuous numbering `lecture-01`–`lecture-32` (2 h each; 32 × 2 = 64 contact hours).

| Module | Directory | Lectures |
|---|---|---|
| M1 Security Foundations & Threat Modeling | `module-01-fundamentals/` | L01–L04 |
| M2 Web Application Security | `module-02-web/` | L05–L08 |
| M3 Malware Analysis & Social Engineering | `module-03-malware/` | L09–L12 |
| M4 Network Security & Monitoring | `module-04-network/` | L13–L16 (L16 = midterm) |
| M5 Cryptography & Applied Trust | `module-05-crypto/` | L17–L20 |
| M6 Data Science for Security & ML Security | `module-06-ml-security/` | L21–L24 |
| M7 Cloud Security & Privacy | `module-07-cloud-privacy/` | L25–L28 |
| M8 Capstone | `module-08-capstone/` | L29–L32 |

Every student note contains, in fixed order: learning objectives · key concepts and definitions · a conceptual diagram (with text description) · realistic examples (CS + DS tracks) · common misconceptions · classroom activities · discussion questions · a problem-solving exercise · summary · exit ticket · references.

**CLO tag convention:** each note's objectives header names its *primary* CLO (and supporting CLOs where one shapes the lecture, e.g. L02 → CLO-4). The complete primary/supporting matrix is authoritative in `../syllabus.md` §5 — notes intentionally do not duplicate it in full.

**Related (not here):** teaching guides, speaker notes, answer keys, and lab delivery instructions are **instructor-only** — see `instructor-materials/instructor-only/` (teaching guides per lecture in `teaching-guides/`, session plans in `lecture-plans/`, keys in `assessments/instructor-only/`). Module overviews and lab worksheets are authored per `docs-meta/implementation-roadmap.md` (Stages 1–5).
